# A-CDM 数据链路与口径校验

更新：2026-11-17。范围为本地现有同步窗口，不补齐更早历史；长沙、南京、郑州继续使用带模拟标识的测试数据。

## 统一口径

| 内容 | 权威来源与关联方式 |
| --- | --- |
| 航班身份 | FIMS、ACDM共享Oracle `FLIGHT_ID`；同日同号的不同运行保留各自身份 |
| 统计航班总体 | FIMS主表关联ACDM；ACDM独有记录留存，不进入本场运行指标 |
| 计划量 | FIMS `PLAN_TIME` 的北京时间自然日，排除任务`A/N` |
| 实际执行量 | ACDM实际起飞/落地时间的北京时间自然日，排除`A/N`与`CAN` |
| 正常与延误 | 直接使用ACDM原生标识、分钟值，不由状态或其他时间反推缺失值 |
| 出港旅客 | FIMS旅客汇总`TBH_FIMS_DYN_CALC_TOTAL.DEP_DPSR_DEPE_NUM` |
| 进港旅客、座位、货邮、行李 | `FORMFILL.FLIGHT_PRODUCTION_ANALYSIS`，不使用`SUM_FLIGHT_PRODUCTION_ANALYSIS` |
| 生产量关联 | ACDM执行日期、FIMS机号、规范航班号、ACDM实际航段；仅计可用座位非零的源记录 |
| 客座率 | 仅纳入已执行且可用座位大于0的同一批航班；样本旅客量除以样本座位数，全量旅客吞吐量单独统计 |
| 过站保障 | FIMS主表范围内，按ACDM原生关联航班ID配对，同机号、有效挡轮顺序，归属实际进港日期 |
| 登机桥 | 完整源主键`FLIGHT_ID + ORDER_CD + AIR_BRIDGE_ID + AIR_BRIDGE_CD`；按实际开始时间统计，原生秒数换算分钟 |
| 节点录入 | 按节点实际记录时间统计；覆盖率按适用方向的当期执行航班去重，次数与航班数分列 |

生产源没有`FLIGHT_ID`。同一生产业务键可以对应不同运行记录；统计视图保留Oracle手册的业务键关联规则，不以本地单一外键任意分配生产量。单航班详情中的外键仅在机号、航段以及必要的运行时刻能唯一识别时设置。生产源缺少运行级身份，不能据此证明每次运行的独立生产量。

执行率分别汇总当期计划量与实际执行量后相除，不先按实际航班过滤计划分母。自然日与运营日明确区分；启用运营日时使用目录中的日切时间。按日、周、月分组跟随指标自身日期字段。高峰小时保留实际日期，跨日区间不将每天同一钟点合并为一个小时。

## 入库修复与失败保护

已修复35组同日同号运行错误合并，按源ID拆分并重建子记录关联。生产数据改用原表、源UUID身份，旧汇总源记录软删除留存。登机桥原先省略主键字段导致的合并已重读恢复；本场航班主属性与ACDM观测字段分属各自源，轮询不会相互覆盖。

ACDM标准记录和原始记录在同一批次事务提交；任一写入失败则整批回滚，不推进水位。生产同步在整轮源数据读取、写入、范围核对、视图刷新成功后统一提交；断连或写入失败时回滚，避免发布半份生产数据。空源结果不会触发范围清理。

修复前的标准表与子表加密备份位于当前管理目录`backups/before-acdm-pipeline-20261116T175301.json.gz.enc`。35组身份修复另有`flight-occurrences-*.json.enc`备份。旧生产行保留软删除标记，不物理清空业务表。

## 可重复执行的核对

在项目根目录运行，使用本机已有连接配置；脚本不输出连接凭据，不修改Oracle或PostgreSQL业务数据：

```powershell
$env:HBASK_DATA_SOURCE = 'ops_ask'
.\.venv\Scripts\python.exe -X utf8 -m scripts.ops_ask.validate_acdm_pipeline --start 2026-11-09 --end 2026-11-09
.\.venv\Scripts\python.exe -X utf8 -m scripts.ops_ask.validate_acdm_pipeline --start 2026-11-02 --end 2026-11-15
```

Oracle参考SQL独立存放在`tests/fixtures/acdm_oracle_reference.json`。脚本对比全部62项已开放的真实业务指标，检查自然语言问询、通用报告、地服简报、保障看板、分组、筛选、运营日及本场对标座位指标；另外比较6类源记录的完整主键集合，避免总数相等却串行或漏行。任一不一致或查询错误返回非零退出码。

每次核对的两端均使用只读快照，JSON结果记录Oracle快照时间、本体版本、期望值、实际值与缺失/多余源主键。不要在校验过程中重入库或修改统计视图。核对不同日期范围时顺序执行，避免给Oracle增加并发负载。

重点结论：2026-11-09实际执行506架次（出港250、进港256）；2026-11-02至11-15实际执行7003架次（出港3499、进港3504）。7004包含了不在FIMS主表中的ACDM记录4825537。旧会话、导出快照及PDF保留生成时内容，需要重新查询或生成报告。

窗口起止日期仅表示已同步记录的日期边界，不代表首日跨日航班或当天数据已经完整。完整历史回归采用2026-10-17至2026-11-15，并额外核对11月9日、11月2至15日、11月15日。未回填的早期记录与未结束的运行日不应被解释为零。

## 2026-11-17 客座率样本修正

上述历史验证证明当时与手册SQL一致，但手册客座率公式将全量出港旅客与部分有效座位相除，未保证分子分母的航班样本一致。用户提出85.65%与85.27%的差异后，经Oracle复核并确认修正：综合、出港、进港客座率统一使用可用座位大于0的已执行航班样本。旧客座率结果和旧参考答案由本节取代。

2026-11-02至11-15：全量旅客仍为960160人次；客座率样本旅客为955884人次，其中出港481079、进港474805；样本座位1120967个，其中出港567210、进港553757。综合客座率85.27%，出港84.81%，进港85.74%。有效座位样本为6709架次，出港3395、进港3314。

出港3499架次中有104架次未匹配到正数可用座位，其中27架次有离港旅客4276人。这27架次在Oracle使用同一严格关联键也无生产记录匹配，部分同日同号生产记录的机号或航段不同；没有放宽关联条件或补造座位，也未重写源数据。本次修正计算表达式、参与记录数、明细范围、报告摘要及参考SQL，不需要全量重新入库。

问询和报告明确区分“全量旅客吞吐量”与“客座率样本旅客量”；有效样本为空时客座率返回无有效数据，不返回0或无穷大。新增测试覆盖零、空、负座位以及多航班加权汇总。新的独立Oracle参考名为“有效座位同航班样本客座率”，核对结果位于`artifacts/analysis-qa/pipeline-seat-*.json`。

本次四个窗口各125项、合计500项Oracle对照全部通过；包括三类客座率的样本架次，以及报告中的样本旅客、座位、覆盖架次和被排除旅客数。相关152项测试通过。全量后端492项仍有4项失败、1项错误、19项跳过，均为既有权限相关检查，未新增统计失败；日志为`artifacts/analysis-qa/load-factor-backend.log`。
