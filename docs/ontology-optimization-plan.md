## 通用架构与业务规则

目录与 SQL 引擎不含“某表就走某分支”的主体判断。数据库允许范围内新增表会自动发现；中文注释用于召回，人工配置提供业务绑定和指标。新资金/会议等关系通过同一规则文件生效。

配置对象：

- 实体：名称、别名、身份字段、记录粒度。
- 属性：原注释、解释、映射、类型、单位、枚举；支持 JSON 路径。
- 关系：完整字段对、方向、角色、约束推导基数、来源和状态；配置 via 消歧。
- 指标：明确字段、单位、默认口径和分组；不接受任意模型表达式。
- 状态：candidate / configured / confirmed / disabled / invalid；candidate、disabled、invalid 不执行。

当前兼容使用 configured 和历史提示边。它们经过结构校验，但仅业务审核能赋予 confirmed 含义；没有依据不能由模型自动审核。抽样检查只展示数据证据，不把高匹配率当作唯一键证明。

## 关键准确性规则

1. 企业简称先转规范代码；不能再用简称与企业全称精确比较。同名人员必须补充身份。
2. 模型不能修改已经确定的查询主体/统计粒度，或删除确定性的姓名、企业、时间条件。
3. 无效字段、空条件、缺失时间/金额口径明确拒绝，不能静默扩大查询范围。
4. COUNT/SUM 与分页是相同筛选范围，关联不能只取前 50 个主记录。
5. 多条一对多关系分别查询，相关条件用 EXISTS；目标记录去重。
6. 资金按币种和交易类型分组；类型枚举未知就保留编码，不自行翻译收/付款性质。
7. 合同金额、付款计划和实际交易不能混用；余额快照不逐笔累加。
8. 薪酬非数字值不猜测、也不静默漏算；业务时间不能用创建时间代替。
9. 明细展示全部允许字段不等于把所有记录送模型；证据标记提供量、总量和长字段摘录。
10. 失败或证据不足时返回事实摘要；答案数字检查仍需搭配业务样例和人工抽检。
