# hbairport01 问答数据权限

问数页与管理后台统一使用 hbairport01 的现有用户体系，业务库保持只读。账号、密码、部门、角色、菜单和权限直接读取现有表；本服务不创建、复制或维护用户表。SQLite 仅存登录令牌摘要和原用户 ID，以及模型配置、问答记录和审计。权限校验始终启用，没有访客或本地用户模式。

## 原项目核对结果

来源：`D:/project/gzwtb/backend/src/main/java/com/ztzh/govasset/`。

- `security/scope/DataScopeResolver.java`：部门 `owner_org_scc` 锚定法人；企业子树由 `EnterpriseOrgTreeService` 和 `UserDeptEnterpriseRelations` 构建。
- `security/scope/ResolvedDataScope.java`：`DEPT_ONLY` 是本公司；`DEPT_TREE` 是本公司及下属法人；`SELF_ONLY` 是本人填报并处于可见企业范围；`ALL` 或业务角色 `admin` 不限制行范围。
- `security/IndicatorPolicy.java`：任一启用角色 ALL 不限制指标，否则并集白名单；空并集保留原系统“不限制”的兼容行为；填报菜单派生的指标并入白名单。
- `security/PermissionPolicy.java`：有显式权限时使用显式权限；未配置权限时可由启用叶子菜单派生；空并集保留原系统“不限制”的兼容行为。权限点启用状态及角色启用状态实时检查。
- 人力分段授权分别处理；只看人员基础信息不自动开放工资。月薪表中的现金、股权、出售股权激励字段按其分段查看权限移除。
- 模块的企业归属字段采用各服务的实际口径。综合接待只使用企业信用代码，不因集团信用代码而额外放行；工资行按关联员工的企业归属过滤；合同履行可以按自身信用代码或关联国资合同 ID 的企业归属过滤；合作伙伴无所属企业代码的历史行保留原服务的部门/本人归属规则。

## 实现

- `app/business_access.py`：验证现有 bcrypt 密码、账号启用状态，合并启用角色、菜单及权限，解析企业范围。账号、角色、部门和授权每次请求重新读取。
- `data/business_permissions.json`：55 张已核对业务表的指标、查看权限、企业字段和主子表归属映射，并保存原项目企业对应关系。部署不依赖原 Java 项目的运行路径；原项目规则变化时须同步此映射。
- `app/query.py`：每个业务表来源使用带权限条件的派生查询。强制覆盖主体、关联表、中间关联、EXISTS 条件、计数、合计和分页；所有权限值使用参数绑定。
- `app/core.py`：规划器只收到已授权实体及名称候选，模型证据使用已过滤 SQL 结果。计划缓存和分页令牌包含权限版本；执行和输出前复核权限。
- `/api/auth/*`：问数与管理后台共用的账号登录、状态与退出，使用同一个 HttpOnly Cookie；旧 `/api/business-auth/*` 仅为相同接口的兼容别名。没有独立管理员注册或本地改密码接口。
- `/api/conversations/*`：只管理本人会话，旧 `/api/business-conversations/*` 是同一接口的别名。权限变化后隐藏旧答案及执行过程，要求重新提问；旧本地账号记录不按用户名自动转给业务账号。
- 管理后台的模型、系统设置、审计和本体修改权限沿用原项目 `admin` 角色；其他角色可问数和管理本人会话。不存在额外的 editor/viewer 角色。
- 用户、密码、角色和授权统一在原填报项目管理，本服务已移除人员 CRUD、首个管理员注册和访客开关。
- 旧 SQLite 启动迁移前自动保存 `management.before-unified-users-*.sqlite3` 备份，再移除旧 `users`、`credentials` 表及访客设置。模型配置、密钥、会话及审计保留；备份是历史归档，不参与认证。


## 覆盖范围

已映射员工、任职经历、人员明细、月薪及相关子表、企业薪酬台账、人力专项、合同及子表、合同履行、资金、银行账户、资产、采购、企业组织、借贷担保、应收、财会报表、综合接待、合作伙伴和会议等，共 55 张表。精确列表见映射 JSON。

未配置可验证业务归属的表默认不开放，包括系统账号权限表、后台同步/序列表以及尚未映射的投资计划、流程管理和部分提交批次表。不能以“表有企业代码”或“用户是本服务管理员”为理由自动放行。审批权限不会被直接当作问数查看权限。

## 验证

- 新增权限回归：真实 bcrypt 2a/2b 校验、停用账号、未登录及旧 Cookie 绕过、多角色规则、指标分段、企业树、缺少部门、参数顺序、分页撤权、历史撤权及跨账号导出。
- PostgreSQL 事务内临时表验证：跨公司主表/关联/EXISTS/计数/合计/分页隔离，以及完整问答的名称候选和证据范围；测试结束回滚，不写业务表。
- hbairport01 实库只读校验：55 张映射表的 SQL 全部通过 EXPLAIN。
- 前端 TypeScript、Next.js 静态生产构建和前端回归通过。

没有使用真实用户密码做登录测试；密码兼容性在临时登录会话和模拟业务账号中验证。实际使用时请在问数页面登录现有业务账号。
