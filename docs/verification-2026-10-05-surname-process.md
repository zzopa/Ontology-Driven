# 姓氏查询与执行过程验收（2026-10-05）

## 实现与边界

- 依据人员实体的 `name_lookup` 和 `bindings.name/company` 解析姓氏，不写死人员物理表。支持“夏姓员工”“姓夏的员工”和常见复姓。
- 姓氏用 `prefix` 编译为参数化 `LIKE`；保留标准企业代码，不把企业简称与全称错误比较。
- 完整、无其他未解析条件的姓氏查询使用确定性本体规则。其他条件必须映射到真实字段，缺失时拒绝扩大查询范围。
- 模型 `LIKE` 仅可规范明确字面值的单一前缀/包含模式；主体仍必须在相关本体内，不关闭本体、字段和筛选值检查。
- `ExecutionTrace` 记录连接、本体、条件、模型使用/跳过、计划校验、关系、SQL 编译、EXPLAIN、实时取数、证据及回答校验。缓存命中时明确显示计划缓存版本校验，仍实时查数据。
- NDJSON `step` 事件实时更新同一阶段，前端可折叠；成功与正常失败过程加密保存并可从历史会话恢复。异常发生在两个阶段之间时也保留失败条目。
- 展示实际执行信息，不展示内部思维链、原始推理、提示词或模型密钥。旧记录和服务硬中断前未保存的步骤不能事后伪造。
