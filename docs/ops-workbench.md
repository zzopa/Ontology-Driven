# 独立运行工作台

运行工作台使用独立 `/ops` 页面、`/api/ops` 接口和运行台账，保留原问答页面与 `/api/ask` 的行为。当前静态演示覆盖 T2 / T3，支持保洁、加油、配餐、装卸、登机。

## 当前：全部页面使用静态测试 JSON

按当前请求，五个 `/ops` 页面及已有 `/api/ops` 接口统一切换到 `data/ops-test-data.json` 的虚构测试场景。固定时间为北京时间 **2026-11-10 10:32**；旧书签中的 `at` 或 `mode=live` 不会切回真实数据。原问答页面、`/api/ask` 和原问答数据源保留现有行为。

JSON 包含27班航班（T2 12班、T3 15班）、135项五类保障作业、40个班组、75个物理机位（T2 20、T3 55）及3个动态监控点、排班与转场依据、8项风险、14条方案记录、12张不同状态工单及处置事件。首页、航班下钻、资源负荷、跨航班前后排程、方案切换、工单历史和班组管理均从同一文件展示，不再用残缺实绩填充页面。

核心场景：A班组同时保障CZ3103与HU7134；B班组可转场2分钟接替CZ3103，完成后转场4分钟衔接CA1258，保留2分钟余量。另包含配餐超时、装卸设备故障、待核验、待接单、执行中和已完成状态。

当前是**只读展示**。页面关闭审批、派单、接单、报工及配置修改；后台也对所有写请求返回405，避免旧页面或直接请求改动台账。筛选、刷新、下钻、切换方案和历史查看仍可用。协同区展示JSON场景摘要，交互问询暂不执行。

登录与原运行岗位授权仍生效。静态业务展示不从业务库或旧运行台账补数据；非管理员的岗位权限仍复用既有授权。JSON缺失或损坏时明确报错，不自动回退到真实数据。已有两套运行台账保留，未清空，也未启动后台值守。

修改测试数据时直接编辑JSON，后端每次请求重新读取；网页刷新即可更新。恢复真实/历史预演接入时，将 `app/ops/api.py` 的 `STATIC_TEST_DATA` 改为 `False` 并重启8088，页面会恢复原时间选择、权限与业务流程。前端仍采用静态导出，无额外Node生产服务。


后端代码更新后按原服务启动方式重启 FastAPI。原问答页不增加入口，新页面直接访问：

- `/ops/resources`：班组、排班、现有任务、转场、规则、授权与试运行开关。

## 从真实数据开始配置

1. 使用原业务账号登录。原系统 admin 可管理运行台账；其他账号由管理员在新班组管理页赋予值守查看、调度或绑定班组报工岗位。不会因此获得原问询的新权限。
2. 登记真实班组、作业类别、有效资质、必要设备，并明确确认当前位置和空闲/忙碌状态，10分钟有效；未知状态不参与推荐。所属班组长也可在工单中心确认状态。保障类别创建后不直接更改。
3. 登记班次与完整现有任务，包括当前窗口之外、跨日的后续任务。按业务日检索真实航班。拟调配任务必须填写业务确认的最晚保障结束时间，依据本航班前后作业及现场规程确认，不能直接把TOBT作为作业截止。源记录机位缺失时可单独登记人工确认机位，始终标注人工来源。
4. 登记定向、实测的机位间转场时间。不会按编号、示意图像素或直线距离推算；不同方向分别维护。
5. 逐类核实标准耗时与记录宽限，并勾选业务确认。未确认的规则不作确定的超时判断，也不生成可执行调配建议。
6. 正式台账须在影子值守和现场验收后，由管理员显式开放人工审批；正式审批默认关闭。模拟台账默认允许完整模拟流程，模拟配置不能充当现场验收依据。

没有班组或排班时，资源缺口显示待配置而不是零。资源负荷仅覆盖已登记任务和已确认能力，不代表已覆盖所有外部任务。源标准字段与 ext_json 的作业时刻在新适配层统一，原问询读法保持不变。未来或倒序实绩会标记待核查，不计为完成。

## 独立值守进程

不随问答服务启动，不创建系统计划任务。管理员显式运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.ops.worker --terminal T2
```

默认每30秒按默认预演时钟扫描本地历史数据并持久化到模拟台账，**不启动 Oracle 采集**，不逐航班调用模型。网页选择的时刻只影响当前页面的按需快照，不改变后台进程时钟。同一机器、航站楼、模式使用进程文件锁，避免重复启动。

完成实时数据改造后，明确指定正式模式才复用现有 FIMS/ACDM 航班、保障节点增量同步，再扫描规则；不执行历史全量清理：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.ops.worker --terminal T2 --mode live
```

只扫描已有本地副本，不推进采集新鲜度：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.ops.worker --terminal T2 --mode live --once --no-sync
```

网页每15秒读取按需快照，隐藏时暂停轮询。未启动进程时明确显示“按需快照”，不能据此声称后台持续值守。正式模式下 FIMS、ACDM、保障节点三类采集成功时间均须在2分钟内，且无失败记录；失联、采集失败或扫描失败时暂停自动推荐。源端不新鲜时不自动解除已有源数据告警。历史预演明确标为非实时，不使用当前采集新鲜度阻止模拟排程。

采集连接复用本机既有配置和加密模型管理，不复制账号密码。运营库连接只读；增量同步仅通过已有同步写连接写本地标准库。

## 调配与工单

先登记任务再预演。候选先检查本航班经业务确认的可调配窗口、作业能力、有效资质、设备、在岗、位置与忙闲确认、占用、前后转场及后续排班；相同拟开始时间下按转场时间排序。缺依据时返回具体缺项，不生成评分。首期没有自动推断未确认节点依赖，调度须核对现场作业条件。

方案有效期5分钟。审批要求版本和防重复标识，并重新读取所有关联航班及最新台账。机位变化、任务开始、采集延迟、排班或资源变化时要求重新计算。SQLite 写事务同时校验资源占用与生成唯一工单；重复提交同一防重复标识返回已有工单。

方案状态：待审批 → 已批准 / 已驳回（过期在界面标明）。

工单状态：待接单 → 已接单 → 执行中 → 待核验 → 已完成；另有异常和取消。开始/结束报工可填写实际时刻，不能填写未来或倒序时刻。拒单、异常、取消及核验必须说明依据。班组只能处理绑定班组，核验和取消由调度负责。

原有人工登记任务也可从工单中心报工；已有工单的任务必须通过工单流转，不能绕过工单改状态。源实绩与人工报工分列展示；人工完成不等于源记录已回传，核验明确标为人工核验。

协同首版为确定性快照说明，可解释风险、已登记资源及指定航班。它不依赖模型可用性，不直接审批或派工；通用问数继续使用原智能问询。

## 地图自由交互

地图滚轮以鼠标所指位置为缩放锚点，左键拖动平移，右键或Shift+左键拖动旋转；单指平移，双指缩放/旋转。平移沿机坪地面进行，不锁定原有中心。机位标签与画布共用交互区域，在标签上也能缩放和拖拽；只有未发生拖动的主键点击才选中机位。拖动后回到起点、右键和多指手势不会误触发航班聚焦。

手动操作立即取消预设镜头的补间移动，后续渲染不重新设置目标点；仅主动点击全景、航站楼、聚焦或重播时重新使用预设视角。
